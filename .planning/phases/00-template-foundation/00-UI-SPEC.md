# Phase 0 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> This phase CREATES the design system: there is no existing UI, no `components.json`, no tokens (empty repo).
> Every future app inherits this contract — deviations must be explicit per-app overrides, never rewrites.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (latest v4 CLI) + Tailwind v4 CSS-variable theming |
| Preset | none pre-built — init parameters prescribed below (zinc base) |
| Component library | Radix UI primitives (wrapped by shadcn) |
| Icon library | lucide-react (shadcn default) |
| Font | Geist Sans (UI) + Geist Mono (code), self-hosted via `next/font` → `--font-sans` / `--font-mono` |

**Init parameters (executed in plan 00-01 — canonical, not negotiable):**

- `npx shadcn@latest init` → baseColor `zinc`, `cssVariables: true`, RSC enabled, `components.json` written at repo root
- `globals.css` follows the shadcn v4 scaffold exactly: `@import "tailwindcss"`; `@custom-variant dark (&:is(.dark *))`; `@theme inline` mapping all tokens below; `:root` + `.dark` blocks; `@layer base` with `* { @apply border-border outline-ring/50; }` and `body { @apply bg-background text-foreground; }`
- Theme provider: `next-themes` → `attribute="class"`, `defaultTheme="system"`, `enableSystem`, `disableTransitionOnChange` (prevents flash + transition flash on theme switch)
- Components added via `npx shadcn@latest add <list>` — see Component Inventory

**Token authority:** if CLI-generated defaults differ from the tables below, the executor applies the values in this contract. Semantic roles are the contract; the oklch values are canonical.

**Design direction (rationale):** Cool-toned neutral base (zinc) with a single indigo accent — the "modern SaaS" family (Linear/Vercel-esque). Zinc reads clean, professional, and hiring-manager-safe while indigo gives the template identity and avoids the generic near-black-on-white default. Neutral dominance means any future app can re-brand by overriding `--primary` (one line), which the 30-project portfolio needs. Geist is the Vercel-native sans: crisp at small sizes, no external font requests (self-hosted), zero layout shift. Radius 0.75rem (vs default 0.625rem) softens cards for a more contemporary feel. All decisions below are defaults chosen because they serve the "clean professional portfolio" context — each is a one-file change if the user later disagrees.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside buttons/rows; internal icon padding |
| sm | 8px | Compact gaps (avatar to name, badge to title, cell inner padding `p-2`) |
| md | 16px | Default stack gaps (form fields `gap-4`, list items, `px-4` page gutter on mobile) |
| lg | 24px | Card padding (`p-6`), section-to-section gaps, `gap-6` grids |
| xl | 32px | Page-header to content gap, `gap-8` card grids, `py-8` page padding |
| 2xl | 48px | Major section breaks (landing feature grid to footer, `gap-12`) |
| 3xl | 64px | Page-level padding (`py-16` landing hero, admin content `p-8`) |

Exceptions (documented, intentional):
- Icon-only buttons: 40 × 40px minimum touch target (`h-10 w-10`) — exceeds 32px for touch usability
- Landing hero vertical padding `py-20` (80px) for emphasis — the only 20-unit usage
- Container widths: content `max-w-5xl` (1024px); auth card `max-w-md` (448px); admin content `max-w-6xl` (1152px)

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Page text, table cells, form field content, descriptions |
| Label | 14px | 600 | 1.4 | Form labels, button text, table headers, nav items, timestamps, badge text |
| Heading | 20px | 600 | 1.2 | Card titles, section headings, page-header titles |
| Display | 28px | 600 | 1.1 | Page titles (`text-3xl`), landing H1, admin page titles |

Weights: exactly 2 declared — **400 (regular)** for body, **600 (semibold)** for labels/headings/emphasis. Shadcn-generated `font-medium` (500) on form labels and buttons is accepted as the label weight (documented exception — it is baked into generated components; do not add weights above 600, do not use italic for emphasis).

Exception: landing hero H1 renders at 36px (`text-4xl`), weight 600, line-height 1.1 — display emphasis only.

Details:
- Headings: `tracking-tight` (-0.025em). Body: normal tracking
- Code/mono (`--font-mono`): 14px, used for env names, code blocks, `kbd` — never for body copy
- Page hierarchy rule: one H1 per page; sections use H2 (Heading role); cards use H3 (Heading role) — no skipped levels

**60 / 30 / 10 split:**
- **Dominant (60%)** — `background`, `foreground`: page shell and body text
- **Secondary (30%)** — `card`, `secondary`, `muted`, `accent`, `sidebar`, `border`, `input`: elevated surfaces, nav, hover states
- **Accent (10%)** — `primary` + `ring` only

**Accent (`primary`) is reserved for:** primary buttons; text links; active nav item (header + admin sidebar); focus rings (`ring`); logo mark; default badge; checked switch/checkbox states; hero CTA button. NOT for: card borders, table headers, decorative fills, icons of neutral actions — those use border/muted tokens.

**Destructive is reserved for:** destructive buttons ("Delete"), destructive menu items, error `Alert` icon/border, form error text (`text-destructive`), invalid input border (`aria-invalid` → destructive).

Contrast contract (both modes): body text ≥ 4.5:1 on its surface; large text (≥24px) ≥ 3:1; `muted-foreground` ≥ 4.5:1 on `background` (zinc-500 on white = 4.75:1 ✓; zinc-400 on zinc-950 = 7.3:1 ✓); white on indigo-600 = 6.3:1 ✓; zinc-950 on indigo-400 = 6.7:1 ✓. No gray-on-gray text pairs below 4.5:1 for readable content.

Shadows: Tailwind defaults only — cards use hairline `border` (no resting shadow); interactive cards hover `shadow-sm`; popovers/dropdowns/sheets use shadcn defaults (`shadow-md` family). No custom shadow tokens.

Radius: `--radius: 0.75rem` base; derived scale via standard `@theme inline` formula (`radius-sm = 0.6×` … `radius-4xl = 2.6×`). Applies to cards, inputs, buttons, dialogs, badges, skeleton.

## Interaction & State Patterns

1. **Forms (auth + posts):** client components, react-hook-form + zodResolver + shadcn `form`; validation errors inline under each field (destructive, 14px, with `aria-describedby` link); server-action errors surface as destructive `Alert` above the submit button, never only as toasts; submit button `disabled` + `Loader2` spinner while pending (`useActionState`); disable autofill overrides — native `autoComplete` set (`email`, `current-password`, `new-password`, `name`).
2. **Toast vs inline:** inline errors for ALL form validation and form submit failures (they belong to the field/context); sonner toasts ONLY for success confirmations ("Post created.") and non-form transient info. Never both for the same event. Toaster: `position="top-right"`, `richColors`, `closeButton`, theme-aware (follows `.dark`).
3. **Loading:** route-level `loading.tsx` per route group with skeleton composition (never full-page spinners; never blank flashes); buttons show inline pending spinners; skeletons use `animate-pulse` muted blocks matching final layout dimensions.
4. **Mutations (create/update/delete):** blocking, never optimistic. Rationale: demo apps are judged on correctness; `useTransition`/`useActionState` pending states keep the UI feeling responsive, and server-revalidated data guarantees the table and database agree. Optimistic UI is deferred to Phase 2+ where it adds value.
5. **Destructive actions:** every destructive action goes through `alert-dialog` with the exact destructive copy + destructive variant button (deletes). No inline one-click deletes. Logout does NOT require confirmation (non-destructive, re-login is trivial).
6. **Session expiry:** middleware redirects to `/login?next=…`; after re-login, redirect back to `next`.
7. **Redirection rule:** after login/register → `/dashboard` (or `?next`); after logout → `/`; after create/update post → `/posts`; after cancel in post form → back to `/posts`.

## Responsive Behavior

- **Breakpoints:** Tailwind defaults, mobile-first — `sm` 640, `md` 768, `lg` 1024, `xl` 1280. Decision points: header nav collapses below `md`; feature grids 1→3 cols at `lg`; stat grids 1→3 cols at `md`; admin sidebar becomes off-canvas drawer below `md` (shadcn Sidebar built-in behavior).
- **Header (mobile):** nav links hidden; hamburger (`Menu` icon, ghost icon button) opens `sheet` (right side) with nav links + user menu contents; logo + theme-toggle always visible.
- **Tables:** every table wrapped in `overflow-x-auto` with a sensible min-width (≥640px); columns that can shrink get `truncate` + max-width (Title, Subject, Message); never horizontal-scroll the page.
- **Grids:** card grids stack 1-col mobile, expand at `md`/`lg`; cards keep `p-6` at all sizes.
- **Auth pages:** card width `w-full max-w-md` with `px-4` gutter on mobile; no scroll-jack.
- **Hero:** text left-aligned always (no centered-then-left dance); CTA buttons stack full-width on mobile (`w-full sm:w-auto`).

## Accessibility

1. **Focus:** visible focus ring on ALL focusable elements via `ring` token (`outline-ring/50` base + shadcn component rings); `focus-visible` only (no ring on mouse click); ring offset 2px on light surfaces.
2. **Contrast:** enforced per Color section — body ≥ 4.5:1, muted ≥ 4.5:1 on its surface, primary button text ≥ 4.5:1, focus ring ≥ 3:1 against adjacent surface. Dark mode is not a "less contrast" mode — muted-foreground stays ≥ 4.5:1 (zinc-400).
3. **Semantics/aria:** one `<h1>` per page; all inputs have `<Label htmlFor>`; field errors linked via `aria-describedby` and `aria-invalid` on invalid inputs (shadcn form does this — do not strip); dialogs from Radix (focus trap, `aria-modal`, ESC dismiss, overlay click dismiss); dropdown menus keyboard-navigable (Radix); theme toggle `aria-label="Toggle theme"` + `aria-checked` on active option; user menu button `aria-label="Open user menu"`; icon-only buttons always carry `aria-label` or `aria-hidden` decorative icons.
4. **Landmarks:** `header` (site-header), `nav` (site nav), `main id="main"` (skip-link target), `footer`; skip link "Skip to content" visually hidden until focus (first element in body).
5. **Reduced motion:** `motion-reduce:transition-none` respected on custom transitions; skeleton pulse and backdrop-blur unaffected functionally; Radix/shadcn animations (dialog/sheet/dropdown) are already motion-reduce-safe.
6. **Targets:** icon-only buttons ≥ 40×40px; interactive rows not sole click targets (actions live in dropdown).
