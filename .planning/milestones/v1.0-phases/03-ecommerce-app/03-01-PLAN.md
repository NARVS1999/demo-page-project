<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser FormData → cart/checkout server actions | Untrusted product ids, quantities, and failure checkbox cross into server code. |
| authenticated action → Neon transaction | Server code controls order/payment/inventory writes but must preserve transaction invariants. |
| admin browser → order lifecycle action | An authenticated admin request can request a status transition, refund, and restock. |
| mock service → mock_* tables | Payment/email writers persist simulated events and foreign-key links. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | checkout inventory/order transaction | high | mitigate | Lock cart product rows, re-read price/stock, use guarded decrements, insert snapshots and clear cart only in the success branch inside `withPool` (SHOP-06, D-05/D-09). |
| T-03-02 | Tampering | simulated payment failure branch | high | mitigate | Persist the failed mock event through the PoolClient, return a committed failure result before inventory/order/cart writes, and throw unexpected errors so `withPool` rolls back (D-08/D-10). |
| T-03-03 | Spoofing | cart and checkout actions | high | mitigate | Re-check `getCurrentUser()` inside every action and scope every cart/order read/write to the session user; UI gating is not the security boundary (D-03). |
| T-03-04 | Elevation | `app/admin/orders/actions.ts` | high | mitigate | Keep actions under the existing admin route/session boundary, re-check the session, allowlist status transitions, and return generic stale/illegal responses; do not expose ownership data. |
| T-03-05 | Tampering | order cancellation refund/restock | high | mitigate | Conditional lifecycle update plus one transaction containing all inventory restoration and `payment.refund(id, client)`; ready/cancelled states are rejected (D-12). |
| T-03-06 | Information Disclosure | `/orders/[id]` data consumed by UI plan | medium | mitigate | UI plan must query by `order_id AND user_id` and use the same `notFound()` for malformed, unknown, and non-owned ids (D-11). |
| T-03-07 | Injection | catalog filters and action ids/quantities | medium | mitigate | Allowlist filter/status values, validate UUIDs and quantities with Zod, and use tagged SQL for one-shots or `$n` parameters for PoolClient queries; never interpolate user input into SQL. |
| T-03-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install task exists; the phase reuses the pinned dependency graph and adds no registry artifact. |
</threat_model>
