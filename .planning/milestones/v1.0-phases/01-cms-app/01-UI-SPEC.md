## Typography

Inherited roles (Body 16/400/1.5, Label 14/600/1.4, Heading 20/600/1.2, Display 28/600/1.1) apply unchanged.

**Phase 1 additions — article reading roles (editorial exception, mirrors Phase 0's newspaper display roles):**

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Article lead | 16px | 400 | 1.75 | Body paragraphs in `/blog/[slug]` and editor preview — 1.75 for long-form reading |
| Article H2 | 24px | 600 | 1.2 | `##` headings in markdown content (`mt-8 mb-3`) |
| Article H3 | 20px | 600 | 1.3 | `###` headings in markdown content |
| Drop cap | `text-5xl` float | 700 | `leading-[0.8]` | First paragraph of article body ONLY — `first-letter:float-left first-letter:mr-2 first-letter:font-serif first-letter:text-5xl first-letter:font-bold first-letter:leading-[0.8] first-letter:text-primary` (matches landing hero) |
| Reading time | 10px mono | 400 | — | "5 min read" in the article dateline row (`uppercase tracking-[0.12em] text-muted-foreground`) |
| Editor mono | 14px | 400 | 1.6 | Markdown textarea (`font-mono`), slug input, markdown inline `code` — per Phase 0 mono rules |

**Markdown content styles (`article-body` / `markdown-preview` shared class set — no `@tailwindcss/typography` plugin, token-based):**

| Element | Style |
|---------|-------|
| `p` | 16px serif, 1.75, `mb-4`, `text-foreground`; first `p` in article gets drop cap |
| `a` | `text-primary underline underline-offset-4 hover:text-primary/80` |
| `strong` | `font-semibold` (600) |
| `em` | serif italic |
| `h2` / `h3` | per table above; `h1` is never allowed in markdown body (title is the page H1) |
| `ul` / `ol` | `pl-5 mb-4`, markers `text-muted-foreground`, nested lists indent `pl-5` |
| `blockquote` | `border-l-2 border-primary pl-4 italic text-muted-foreground my-4` |
| inline `code` | `font-mono text-sm bg-muted px-1.5 py-0.5 border border-border` (sharp corners) |
| `pre` | `font-mono text-sm bg-card border border-border p-4 overflow-x-auto mb-4` — horizontal scroll inside the block only |
| `hr` | `my-8 border-t border-border` |
| `img` (in body) | `w-full border border-border my-6` — plain `<img>`, no `next/image` (untrusted/mock URLs) |
| `table` (GFM) | `w-full text-sm border-collapse my-4`; `th`/`td` `border border-border px-3 py-2`; `th` `font-semibold text-left` |

**Security note (locked):** react-markdown escapes raw HTML by default — markdown content is rendered as rendered-markdown only, never as raw HTML (`skipHtml` behavior kept). Seed content must not rely on raw HTML. All post content is untrusted input rendered inert.

## Interaction & State Patterns

1. **Status workflow (locked: draft/published):** public pages select `published = true` only; admin table + editor show both. Status is a segmented control — two square buttons "Draft" / "Published" in a `bg-muted` container, active segment = `bg-background border border-border shadow-sm` (paper-in-paper, no primary fill — primary is reserved for badges/CTAs). Helper text under it: "Drafts are visible only to you."
2. **No autosave (decision):** the editor persists ONLY on explicit submit — consistent with Phase 0's blocking, never-optimistic mutation rule. Textarea content survives client re-renders but is lost on navigation unless saved. No timers, no dirty-flags, no beforeunload prompts.
3. **Blocking mutations (inherited):** `useActionState` pending → submit disabled + `Loader2`; server errors → destructive Alert above the action row (never only a toast); success → sonner toast + redirect + `router.refresh()`. Toasts: "Draft saved." / "Post published." (create + edit, keyed off final status) / "Post updated." (published → published edit).
4. **Slug behavior:** `editor-shell` auto-derives slug from the title on blur (lowercase, non-alphanumeric → `-`, collapse repeats, trim dashes). Slug input is always visible + editable (mono, `max-w-sm`); validation regex + inline error; duplicate-slug server error → destructive Alert.
5. **Image upload flow (locked: mock storage):** `cover-upload` → client validates (image/*, ≤ 3 MB) → `POST /api/uploads` (route handler: reads FormData `file`, converts to base64 string `data`, calls `storage.upload({ name, data })` from `@/lib/mock` — server-only) → 201 `{ url, size }`. States: idle ("Upload cover") → uploading (disabled + "Uploading…") → success (preview pane + "Remove") → failure (destructive Alert "Cover upload failed. Try again." — upload stays retryable, form data preserved). The returned `url` is stored in hidden field `cover_image`. **Honest-mock behavior (documented):** mock URLs (`https://mock.storage/…`) do not resolve; public cards hide broken covers via `cover-image` `onError`; the editor preview shows a muted placeholder with "Mock cover — URL only"; seed covers use `picsum.photos` seeded URLs so the demo renders real photos immediately.
6. **Search UX:** `blog-search` form `GET` → `/blog/search?q=…` (server-rendered results — no client fetch, no debounce needed); query trimmed, max 100 chars, empty → redirect `/blog`; results page reuses the Features grid + `blog-card`s; count line distinguishes "1 result" / "N results".
7. **Tags input:** Enter/comma adds (trim, dedupe, ≤ 8); `Backspace` on empty input removes last; chips are removable individually; serialized as `tags` comma-joined string (server splits + upserts `tags`/`post_tags`). Admin tag management uses dialogs, not this input.
8. **Destructive actions (inherited + extended):** all deletes go through `alert-dialog` with exact copy; category delete warns about uncategorization; tag delete warns about join removal; blocking pending on the destructive button; success toast.
9. **Toast vs inline (inherited):** inline for validation/upload/server errors; toasts only for success confirmations.
10. **Draft privacy:** drafts are owner-visible only — in `/posts` (existing rule) and `/admin`; public routes never see them (404 on slug access).

## Accessibility

All Phase 0 rules inherited (focus rings, contrast ≥ 4.5:1, one H1 per page, labeled inputs, Radix dialogs, 40×40 targets, landmarks, reduced motion, `lang="en"`). Phase 1 additions:

1. **Markdown headings:** article H1 = the page title; markdown body may only use `h2`/`h3` (executor strips/skips `h1` in markdown — never render two H1s).
2. **Preview pane:** `aria-label="Markdown preview"`; NOT `aria-live` (per-keystroke SR announcements would spam). It is a tool, not primary content.
3. **Cover images:** always `alt` — post title when the cover is the post's own image (`alt={`Cover for ${post.title}`}`), decorative placeholders `aria-hidden`.
4. **Tags input:** labeled (`Label htmlFor="tags-input"`); each chip remove button `aria-label="Remove tag {name}"`; Enter adds (form does NOT submit on Enter inside the tag field — keydown preventDefault); `Backspace`-pop is a nicety, chips remain fully keyboard-removable.
5. **Segmented status control:** `role="radiogroup"` with two `role="radio"` buttons, `aria-checked`, arrow-key navigation; current status announced on focus.
6. **Slug/category/tag inputs:** `aria-invalid` + `aria-describedby` inline errors (shadcn form pattern); `autocomplete="off"` on slug + tag inputs.
7. **Search:** input `aria-label="Search the blog"`, results announced via the page H1 + count line (SR users land on the H1 after GET navigation).
8. **Image upload:** file input visually hidden but focusable (button toggles it); upload failure surfaces in a destructive Alert that the focus follows (dialog-free but `role="alert"`).
9. **Drop cap:** decorative text styling only — the paragraph's real text remains readable and selectable (no `aria-hidden` on content).
10. **Contrast:** cover placeholder, preview panes, chips, and kickers all use Phase 0 tokens (muted ≥ 4.5:1 on its surface; primary kickers ≥ 4.5:1 on washi — verified in both themes).
